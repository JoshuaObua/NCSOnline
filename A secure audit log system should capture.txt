# Core Audit Log Fields

| Field Name       | Description                                                      |
| ---------------- | ---------------------------------------------------------------- |
| `log_id`         | Unique identifier for the log entry                              |
| `event_id`       | Unique identifier for the specific event type                    |
| `timestamp_utc`  | Exact UTC date and time of the event                             |
| `timezone`       | User/system timezone at event time                               |
| `event_type`     | Category of action (LOGIN, CREATE, UPDATE, DELETE, EXPORT, etc.) |
| `event_action`   | Specific action performed                                        |
| `event_status`   | SUCCESS, FAILED, DENIED, ERROR                                   |
| `severity_level` | INFO, WARNING, ERROR, CRITICAL                                   |
| `description`    | Human-readable event description                                 |
| `message`        | Detailed log message                                             |

# Recommended Event Types

A professional audit system should log events like:

* Authentication attempts
* Password changes
* MFA enrollment/removal
* Role & permission changes
* Record creation/update/deletion
* Financial transactions
* Data exports/downloads
* File uploads
* API usage
* Failed access attempts
* Configuration changes
* System errors
* Security alerts
* Backup/restore operations
* User impersonation
* Session timeout/logout
* Device registrations
* Policy violations

---

# Security Best Practices for Audit Logs

## Logs Must Be

* Immutable (tamper-resistant)
* Encrypted at rest
* Encrypted in transit
* Time synchronized (NTP)
* Centrally stored
* Access controlled
* Retained per compliance requirements
* Digitally signed
* Monitored in real-time
* Backed up securely
